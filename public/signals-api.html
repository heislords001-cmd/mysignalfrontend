Signals API

Read the latest signals from your own program. Works for members with an active plan.

1. Get your key

Sign in on the site, open the Profile tab, and tap Create my key. Copy the key straight away: it is shown only once.

Your key only works while your plan is active. Creating a new key replaces the old one. Revoke my key stops it at any time.

2. Address

GET /api/signals

3. Send your key

Put the key in the Authorization header:

Authorization: Bearer YOUR_KEY

curl

curl -H "Authorization: Bearer YOUR_KEY" "https://mysignalfrontend.vercel.app/api/signals"

Python

import requests

r = requests.get(
    "https://mysignalfrontend.vercel.app/api/signals",
    headers={"Authorization": "Bearer YOUR_KEY"},
    params={"approved_only": 1},   # leave out to include untested signals
    timeout=20,
)
data = r.json()
for s in data["signals"]:
    print(s["symbol"], s["side"], s["entry"], s["sl"], s["tp1"], "approved" if s["approved"] else "untested")

4. Options

OptionWhat it does
approved_only=1Only signals that passed the test. Leave it out to include untested signals too.

5. What you get back

{
  "ok": true,
  "count": 2,
  "signals": [
    {
      "symbol": "EURUSD",
      "side": "buy",
      "timeframe": "M15",
      "strategy": "trend_pullback",
      "entry": 1.10040,
      "sl": 1.09800,
      "tp1": 1.10600,
      "tp2": 1.10900,
      "approved": true,
      "agreement": "H1 agrees · H4 agrees",
      "risk_warning": null,
      "expires_at": "2026-11-20T14:00:00+00:00",
      "created_at": "2026-11-20T12:00:00+00:00"
    }
  ],
  "note": "..."
}
  • approved: true means the strategy passed the test. false means it is untested.
  • sl, tp1, tp2: the stop and targets from the scanner. Size them to your own account.
  • risk_warning: set when the stop costs more than the budget at the smallest lot.
  • Only the last 24 hours of signals are returned, up to 30 at a time.

Start the scanner (so signals keep coming when you are offline)

The scanner runs on GitHub. It only runs while someone has signals switched on, so you start it with your key. Once it is running, you don't need to be online. Signals keep being saved while it runs, and you read them with GET /api/signals whenever you like.

Check first. Before you start anything, ask whether the scanner is already running:

curl -H "Authorization: Bearer YOUR_KEY" "https://mysignalfrontend.vercel.app/api/scanner-control"

If running is true, do not start it. It is already dropping signals, so just read /api/signals. Only start it when running is false. If you start it anyway while it is running, you are simply connected to the same run: no second scanner is started.

Start (only when it is not running)

curl -X POST -H "Authorization: Bearer YOUR_KEY" -H "Content-Type: application/json" \
  -d '{"action":"receive_on"}' "https://mysignalfrontend.vercel.app/api/scanner-control"

Stop (your signals switch off; the scanner stops only when nobody else is receiving)

curl -X POST -H "Authorization: Bearer YOUR_KEY" -H "Content-Type: application/json" \
  -d '{"action":"receive_off"}' "https://mysignalfrontend.vercel.app/api/scanner-control"

The reply tells you whether it is running:

{ "ok": true, "receiving": true, "running": true, "started": false,
  "note": "Your signals are on. Connected to the scanner that is already running." }

How long it runs. One scanner run lasts up to about 5.5 hours, then it stops on its own. Check running in the reply, and if it is false start it again with the same call. Starting it while it is already running just connects you to it, so it is safe to call again.

Only one scanner ever runs at a time, however many keys start it.

Errors

StatusMeaning
401The key is missing or wrong. Create a new key on the Profile tab.
403Your plan is not active. Renew it, then try again.
405Use GET.

Important

Untested signals have lost money in every backtest so far. If you trade from this feed, use approved_only=1, and never share your key. Anyone with your key can read the signals on your plan.
